# 運用サイクル

## サイクル概要

```
┌─────────────────────────────────────────────────────┐
│  サイクル1: 調査・方針                               │
│  戦略企画 → 市場レポート ──→ CEO判断                 │
│                                                     │
│  サイクル2: 開発                                     │
│  CEO指示 → CTO設計 → エンジニア実装 → デバッガー検証  │
│                       ↑ バグ発見時ループ ↩            │
│                                                     │
│  サイクル3: 評価                                     │
│  CFO損益レポート + 顧客FB ──→ CEO最終レビュー         │
│                                                     │
│  サイクル4: ガバナンス（社長の判断後に発動）          │
│  倫理委員会 → バイアス・違反チェック ──→ 株主レビュー  │
│  ※ 問題なし → 続行 / 問題あり → 社長に差し戻し      │
└─────────────────────────────────────────────────────┘
```

## 呼び出しパターン

| ユースケース | 起動するエージェント |
|---|---|
| 新戦略を試したい | サイクル1→2→3→4 をフルで回す |
| バグが出た | デバッガー + エンジニア + CTO |
| 成績確認したい | CFO + 顧客 |
| 社長の判断に不安 | 倫理委員会 + 株主 |
| 全体見直し | 9人フルで1回回す |

## トークン消費の目安

| 構成 | 推定トークン/回 | 月額目安（Opus） |
|---|---|---|
| 社長のみ | ~10K | 低 |
| 3人（CEO+CTO+Eng） | ~50-80K | 中 |
| 7人（監視機関なし） | ~150-250K | 高 |
| **9人フル（監視機関込み）** | **~200-350K** | **かなり高** |

> まず1回フルで走らせてトークン量を確認し、日常運用では3-4人体制に絞るのが現実的。
